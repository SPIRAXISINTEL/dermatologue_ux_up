# Cloudflare Pages — manual ZIP / Direct Upload (Windows)

## Important architecture constraint

This project is not a static-only website. It includes Cloudflare Pages Functions in `functions/`, a D1 database binding named `DB`, a protected CMS, a dynamic CMS sitemap, and an appointment-request endpoint. Cloudflare's dashboard drag-and-drop upload does not compile the `functions/` directory. A dashboard ZIP upload would publish static assets but leave those dynamic routes unavailable.

**Use Wrangler Direct Upload for the complete production release.** This still uses the Direct Upload deployment model and uploads the complete project from your computer, including Pages Functions and the Wrangler configuration.

## 1. Extract the ZIP

1. Download and extract the ZIP completely (do not open `index.html` from inside WinRAR).
2. Open the extracted project folder. It must contain `index.html`, `assets/`, `functions/`, `migrations/`, `wrangler.toml`, and `package.json` at the same level.
3. Do not rename or move the `assets/` or `functions/` folders.

## 2. Preview the design locally

Double-click `START-LOCAL-PREVIEW.bat`, then open `http://localhost:8080/`.

This local static preview checks the CSS, JavaScript, images and navigation. It does not emulate D1, Cloudflare Access, the appointment email provider or Pages Functions.

## 3. Deploy the complete project

Prerequisites: Node.js LTS and an authorized Cloudflare account.

1. Double-click `DEPLOY-CLOUDFLARE.bat`.
2. If prompted, sign in to Cloudflare in the browser and authorize Wrangler.
3. The script runs the unit tests and SEO checks before deployment.
4. Wrangler uploads the project to the existing Pages project `dermtanger`.

Equivalent command from the project root:

```bash
npx wrangler pages deploy . --project-name=dermtanger
```

Do not create a new Pages project and do not change the `database_id` in `wrangler.toml` unless you intentionally migrate the existing D1 database.

## 4. Confirm production settings before publishing

In Cloudflare Pages → `dermtanger` → Settings → Functions / Bindings and Variables, confirm:

- D1 binding variable name: `DB`
- D1 database: `dermatologue-tanger-cms`
- `SITE_URL`: `https://dermatologue-tanger.com`
- `CF_ACCESS_ISSUER` and `CF_ACCESS_AUD` are configured for the existing Access application
- `DOCTOR_EMAIL` and optional `CMS_EDITOR_EMAILS` are correct
- `RESEND_API_KEY` is a secret; `RDV_TO` and `RDV_FROM` are configured for the appointment form

These values are not generated by this ZIP. Keep credentials in Cloudflare settings; never paste secrets into HTML or source files.

## 5. Post-deployment smoke tests

Open each URL and confirm HTTP 200:

- `/`
- `/ar/`
- `/dermatologie-medicale-tanger/`
- `/ar/dermatologie-medicale-tanger/`
- `/chirurgie-dermatologique-tanger/`
- `/ar/chirurgie-dermatologique-tanger/`
- `/medecine-esthetique-tanger/`
- `/ar/medecine-esthetique-tanger/`
- `/contact/` and `/ar/contact/`
- `/sitemap.xml`
- `/sitemap-cms.xml`

Then verify:

- `/admin/` is protected by Cloudflare Access.
- `/api/cms/*` is not publicly writable.
- `/api/public/articles` and `/api/public/videos` return JSON.
- `/api/rdv` sends a test request only after the email provider variables are confirmed.
- the CMS can create a draft, submit for review, and publish only through the doctor's authorized account.
- the `*.pages.dev` preview remains `noindex`; the official custom domain remains indexable.

## 6. Search indexing

After production is verified, run a fresh Seobility crawl against `https://dermatologue-tanger.com/`, then submit `https://dermatologue-tanger.com/sitemap.xml` in Google Search Console. Do not submit the `pages.dev` preview as the canonical site.
