# v4.2.0 SEO and security remediation

## Findings from supplied reports
- Seobility could not crawl `https://dermtanger.pages.dev/` because the response carried `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`. This is intentional for the Pages preview hostname and must remain in place. Run the production SEO crawl against `https://dermatologue-tanger.com/` after attaching the custom domain.
- Sitechecker reported the same preview noindex/header mismatch on all 12 pages, plus preview canonicals pointing to the production domain. These are expected preview controls, not production indexing directives.
- Reported source-level issues included nested markup inside the homepage H1, a schedule table without a caption, inline style attributes, image format opportunities, incomplete Twitter image metadata, weak internal links to several advice articles, and missing Arabic content.
- Rank Math/SEORCH reports were generated against an earlier `yassir-6dr.pages.dev` hostname. Their 85/100 score and title-length warning are historical diagnostics, not a verified current production score.
- The security scan reported missing HSTS, permissive CSP, CORS, SPF/DMARC, CAA, DNSSEC, DKIM and MTA-STS. HSTS is emitted only on the production hostname by Pages middleware. The repository does not emit permissive CORS headers; verify any CORS alert against actual production response headers before changing policy. DNS/email items require Cloudflare DNS and mail-provider configuration, not code changes.
